# RA3 · Matriz de contenidos, prácticas y criterios

## Criterios de evaluación completos

| CE | Evidencia exigida |
|---|---|
| RA3.a | Se han identificado las herramientas para diseño y prueba de componentes. |
| RA3.b | Se han creado componentes visuales. |
| RA3.c | Se han definido sus métodos y propiedades con asignación de valores por defecto. |
| RA3.d | Se han determinado los eventos a los que debe responder el componente y se les han asociado las acciones correspondientes. |
| RA3.e | Se han realizado pruebas unitarias sobre los componentes desarrollados. |
| RA3.f | Se han documentado los componentes creados. |
| RA3.g | Se han empaquetado componentes. |
| RA3.h | Se han programado aplicaciones cuyo interfaz gráfico utiliza los componentes creados. |

## Regla de suficiencia

Cada CE necesita un producto observable, una comprobación y una explicación individual. El código generado por IA sin anotaciones, una captura aislada o un paquete que solo funciona en el equipo del autor no son evidencias suficientes.
